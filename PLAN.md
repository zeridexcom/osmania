# Osmania Results Portal — Implementation Plan

## Project context

- **Workspace**: `C:\osmania`
- **Stack**: Next.js 16 (App Router) + React 19 + TypeScript 5 + Tailwind CSS v4 + Supabase (Postgres) + jose (JWT admin auth)
- **Tailwind v4 note**: Config is CSS-first via `@theme` in `app/globals.css`. Do **not** create a `tailwind.config.ts` — extend tokens there. Use the CSS variables exposed in `@theme` (e.g. `bg-heritage-maroon`, `text-on-surface`, `font-headline`).
- **No `middleware.ts`** — Next 16 uses `proxy.ts` and we don't need it (we use route-handler-level auth via jose cookies).
- **`params` and `searchParams` are Promises** — always `await props.params`. Use the global `PageProps<'/path/[slug]'>` helper generated by `next typegen`.

## API

| Path | Method | Purpose |
|---|---|---|
| `/api/result/lookup` | POST | Public: `{ hallTicket, dob }` → returns sanitized `PublicStudentResult` |
| `/api/admin/login` | POST | Public: `{ username, password }` → sets JWT cookie |
| `/api/admin/logout` | POST | Protected: clears cookie |
| `/api/admin/students` | GET/POST | List/create students |
| `/api/admin/students/[id]` | GET/PUT/DELETE | Read/update/delete student |
| `/api/admin/notices` | GET/POST | List/create notices |
| `/api/admin/notices/[id]` | PUT/DELETE | Update/delete notice |

## Grading (OU CBCS convention)

| Marks (%) | Grade | Points |
|---|---|---|
| 90-100 | O | 10 |
| 80-89 | A+ | 9 |
| 70-79 | A | 8 |
| 60-69 | B+ | 7 |
| 50-59 | B | 6 |
| 40-49 | C | 5 |
| 36-39 | D | 4 |
| <36 | F | 0 |

`SGPA = Σ(gradePoints × credits) / Σ(credits)`
`Result status = PASS` if every subject ≥ D and sgpa ≥ 5, else `FAIL`.

## Build order (in this order to keep main context lean)

1. **Backend**: `lib/supabase/{client,server}.ts`, `lib/auth.ts`, `lib/grading.ts` + tests, `supabase/migrations/*.sql`, all API route handlers
2. **Frontend**: shared components (`Header`, `Footer`, `SearchForm`, `ResultCard`, `SubjectTable`, `Sidebar`, `EmptyState`, `Spinner`, `PrintButton`, `StatCard`), then all 7 pages (using mock data initially), then swap to real API
3. **Wire up**: connect frontend `fetch`es to API routes, remove mocks
4. **Verify**: `npx tsc --noEmit`, `npm run lint`, `npm run build`, `npm run test`
